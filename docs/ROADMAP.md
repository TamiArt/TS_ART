# TS·ART Studio — Product Roadmap

This roadmap describes proposed work in dependency order. No milestone should be considered complete until its output has been produced and reviewed.

## Phase 0 — Foundation and decisions

- [x] Record the initial brand direction: TS·ART — TATIANA · ART · QI.
- [x] Record the proposed brand architecture and academy concept.
- [x] Define the initial 20-module curriculum.
- [ ] Check trademark, domain, and social-handle availability in intended markets.
- [ ] Test pronunciation, spelling, and meaning with representative learners.
- [ ] Select a visual direction after reviewing several distinct logo concepts.
- [ ] Decide the first launch language(s) and accessibility baseline.

**Exit criteria:** the brand direction is documented, major risks are known, and the initial scope is agreed.

## Phase 1 — Learning design prototype

- [ ] Fully develop Module 1 (8–12 lessons as an initial target).
- [ ] Create 20–30 mini-studio exercises.
- [ ] Define the shared lesson template and self-check rubrics.
- [ ] Create a skill map with prerequisites and transfer tasks.
- [ ] Prepare a learner journal format.
- [ ] Prototype three to five Colour Lab cards using repeatable experiments and documented materials.
- [ ] Review all historical and technical claims for evidence.

**Exit criteria:** a beginner can complete the prototype without needing undocumented explanations.

## Phase 2 — Beginner validation

- [ ] Test the prototype with actual beginners.
- [ ] Record confusion points, abandoned tasks, completion, and independent transfer.
- [ ] Ask learners to explain the task in their own words before starting.
- [ ] Revise lesson length, examples, instructions, and criteria.
- [ ] Confirm that short exercises connect to the main learning path.

**Exit criteria:** observed feedback has led to specific improvements; do not scale merely because the material looks polished.

## Phase 3 — Product and technical specification

- [ ] Define the first release scope and non-goals.
- [ ] Design responsive learning, lesson, exercise, journal, and portfolio flows.
- [ ] Specify accounts, progress persistence, image uploads, export, and privacy.
- [ ] Define data model and access controls before storing learner work.
- [ ] Decide how optional automated feedback will communicate uncertainty and limitations.
- [ ] Establish content versioning and a review process.

**Exit criteria:** the product can be implemented without guessing about core user flows, data access, or lesson states.

## Phase 4 — Minimum useful academy

Proposed MVP:
- [ ] A navigable learning path and module/lesson pages.
- [ ] A small but complete first module.
- [ ] Mini-studio exercises.
- [ ] Basic progress and skill-state tracking.
- [ ] Private work uploads or an explicitly scoped alternative if uploads are deferred.
- [ ] Learning journal.
- [ ] A small, evidence-aware Colour Lab.
- [ ] Responsive phone/tablet/desktop experience.
- [ ] Clear privacy and image-use controls.

Avoid building every module, a social network, complex gamification, or automated critique before the core learning experience is validated.

## Phase 5 — Expand content and portfolio

- [ ] Expand the core drawing and value modules.
- [ ] Extend the Colour Lab with repeatable pigment tests.
- [ ] Add still life, landscape, sky/water, plants, figure, and portrait modules.
- [ ] Add evidence-based master-study workshops.
- [ ] Add digital painting and cross-media tasks.
- [ ] Add author project and final portfolio routes.
- [ ] Add portfolio curation and export if validated by learners.

## Phase 6 — Launch readiness

- [ ] Check accessibility and responsive behaviour.
- [ ] Review lesson accuracy, image rights, citations, and materials safety.
- [ ] Test account, progress, upload, privacy, and export flows.
- [ ] Test failure states and recovery, including interrupted lessons and failed uploads.
- [ ] Run a limited pilot and prioritise observed issues.
- [ ] Confirm branding clearance and public-facing copy.
- [ ] Publish only content that has passed the defined review process.

## Product metrics to consider

Use a small set of measures that reflect learning rather than vanity:
- Lesson and exercise completion.
- Ability to explain the objective before beginning.
- Successful self-checks and transfer tasks.
- Repeated practice over time.
- Learner-reported clarity and confidence.
- Where learners get stuck and why.
- Quality and completeness of documented work, assessed with transparent criteria.

Do not treat time on platform, streaks, or number of uploads as proof of learning by themselves.

## Ongoing constraints

- Keep the product modular and maintainable.
- Prefer small, testable releases.
- Do not require paid APIs for the core learning path.
- Do not make AI a prerequisite for learning.
- Do not make unsupported historical, scientific, or material claims.
- Protect learner work and avoid public sharing by default.
